## 2. 一条主线：把整门课串起来

> 三份串讲视频的共同做法——用「开机上网访问一个网页」串完所有协议。**任何知识点都要能挂到这条线上。**

```
开机没有 IP
  → DHCP（应用层协议，基于 UDP；服务器 67 / 客户端 68）
      DORA 四步：Discover → Offer → Request → ACK
      拿到四件套：IP、子网掩码、默认网关 IP、本地 DNS 服务器 IP
      源 IP 全程 0.0.0.0，目的 MAC 全 F（广播）
  → 输入域名，先查 DNS（UDP 53）
      本机缓存 → 本地域名服务器 → 根 → 顶级 → 权限
      主机→本地 DNS 用【递归】，本地 DNS→其余用【迭代】
  → 拿到目的 IP，与自己的掩码相与，判断是否同网段
      同网段 → ARP 查对方 MAC
      不同网段 → ARP 查【默认网关】的 MAC   ★ 最高频易错点
  → 封装：HTTP 报文 → TCP 段(80) → IP 分组 → 以太网帧 → 比特流
      上层 PDU = 本层 SDU；本层 SDU + 本层 PCI(首部) = 本层 PDU
  → 交换机：自学习 + 广播帧从所有其他口转发；VLAN 打/去标签（access vs trunk）
  → 路由器：隔离广播域，逐跳查路由表（最长前缀匹配），
      TTL−1、重算首部检验和；★★ 源/目的 IP 全程不变，源/目的 MAC 逐跳改变
  → 出口 NAT/NAPT：私网 IP→公网 IP（NAPT 还改端口号）
  → TCP 三次握手 → HTTP 请求 → 响应 → 四次挥手（TIME_WAIT 等 2MSL）
```

## 3. 第一章：性能指标与交换方式（已升级为计算题重灾区）

### 木桶效应（湖科大反复强调的解题总则）

> **能达到的最高数据传输率 = min(主机接口速率, 信道带宽, 交换机/路由器接口速率)**

**解题注意事项（湖科大原话）**：如果题目**只给了信道带宽、没给数据传输率**，就认为数据传输率可以达到信道带宽——**不要钻牛角尖认为条件不足**。2014 题 36 的"可以达到的最大平均数据传输速率"、2023 题 33 的"所需时间最少"，都是在暗示这一点。

### 两个"带宽"必须分清

| | 频率带宽 | 速率带宽 |
|---|---|---|
| 单位 | **Hz** | **bit/s** |
| 用在哪 | 奈氏准则、香农公式里的 **W** | 时延计算、木桶效应 |

### 单位换算陷阱

- **速率单位**的 K/M/G/T 是 **10³/10⁶/10⁹/10¹²**
- **数据量单位**的 K/M/G/T 是 **2¹⁰/2²⁰/2³⁰/2⁴⁰**
- 严格算它们**不能直接约掉**。命题人常特意写明"M = 10⁶"，**就是为了让你能约掉**——看到这句话说明可以放心约。

### 四种时延

| 时延 | 公式 | 备注 |
|---|---|---|
| **发送时延**（= 传输时延） | 数据长度 / 数据传输率 | **408 真题更爱用"传输时延/传输延迟"这个词** |
| **传播时延** | 链路长度 / 传播速率 | 速率取决于介质，建议记住三种（光速～亚光速）|
| 排队时延 | 无简单公式 | 题目一般会说"不考虑" |
| 处理时延 | 无简单公式 | 题目一般会说"不考虑" |

> ⚠️ **传输时延 ≠ 传播时延**，一字之差本质完全不同。湖科大说弹幕里大量同学混淆——这是送命级易错点。
> ⚠️ 常见错误认知：以为"分组有多少比特就有多少个传播时延"。实际上比特是连续发出的，信号在链路上传播与后续比特发送是**重叠**的，所以 `总时延 = 发送时延 + 传播时延`（类比火车过山洞）。

### 总时延通式（湖科大给的，要理解不要死背）

源主机连续发送 **M 个分组**，经过 **N 个路由器**转发：

```
总时延 = (M + N) × 单个分组发送时延 + (N + 1) × 传播时延
```

**成立条件**：各链路介质/长度/带宽相同，各分组等长，不考虑排队与处理时延，不考虑差错。

**变形**：若题目给的是"经过 **K 段链路**"，则 `N = K − 1`，代入即可。

### 时延带宽积（2023 首考，防再考）

```
时延带宽积 = 传播时延 × 速率带宽    （单位：bit）
```

物理含义：**以比特为单位的链路"长度"**——发送方连续发送时，第一个比特刚到终点，发送方已经发出了"时延带宽积"个比特，它们全在链路上飞。

> 串联记忆：这个概念和**以太网最小帧长的意义**是同一件事的两面。

### 吞吐量（2024、2025 连考）

单位时间内实际通过网络的数据量，**受带宽限制**（同样是木桶效应）。408 里一般只考一个方向。

### RTT

`RTT = 往返传播时延 + 接收端处理时延`；题目说不考虑处理时延则 `RTT = 2 × 传播时延`。
多网络互联时还要加上各路由器的排队/处理/发送时延。**2025 题 47 涉及同步卫星链路，RTT 特别长。**

> 为什么重要：TCP 靠 RTT 算 RTO，**几乎所有 TCP 大题都会给 RTT**。

### 信道利用率（热门考点）

```
信道利用率 = 一次交互中信道有数据通过的时间 / 一次交互的总时间
```

停等协议、GBN、SR、CSMA/CD 都会考它。
> 湖科大提示：**网络利用率至今未考过**，信道利用率才是热门。

### 三种交换方式

| | 电路交换 | 报文交换 | 分组交换 |
|---|---|---|---|
| 建连 | 要 | 不要 | 不要 |
| 独占资源 | 是（利用率低） | 否 | 否 |
| 存储转发 | 否 | 整个报文 | 每个分组（**流水线**） |
| 适用 | 数据量大且传送时间 ≫ 建连时间 | 早期 ARPANET | **因特网** |

分组交换优于报文交换的**本质原因**：报文被切短后，交换结点可以在转发前一个分组的同时缓存后一个 → **流水线传输**，总时延显著下降；且对缓存要求低、误码重传代价小。

## 4. 物理层（1 题，纯公式 + 编码识别）

### 两个极限容量公式

- **奈氏准则（无噪声）**：`C = 2 × W × log₂V`　（V = 码元的离散状态数）
- **香农公式（有噪声）**：`C = W × log₂(1 + S/N)`
  - ⚠️ `S/N(dB) = 10 log₁₀(S/N)`，**给 dB 必须先反解**

### 编码（会看波形写比特串）

| 编码 | 规则 | 特点 |
|---|---|---|
| **NRZ** 非归零 | 全程保持正/负电平 | 编码效率最高，但**要额外时钟线** |
| **RZ** 归零 | 每码元中间回归 0 电平 | **自同步**，但占用带宽更大 |
| **NRZI** 非归零反转 | **码元边界电平不变 = 1，反转 = 0** | NRZ 与 RZ 的折中；USB 2.0 用 |
| **曼彻斯特** | **每码元中间必跳变**，跳变既表示时钟也表示数据 | 传统 10 Mb/s 以太网用；**波特率 = 2 × 比特率** |
| **差分曼彻斯特** | 中间跳变**只表示时钟**；**码元边界无跳变 = 1，有跳变 = 0** | 抗干扰更强 |

> 💡 **湖科大的应试技巧**：曼彻斯特编码有 Thomas 和 IEEE 802.3 两套**相反**的标准，408 不会考区分。做选择题时**随便定义一种**（比如高跳低 = 1）写出比特串，**如果选项里找不到，整串按位取反**即可。

### 调制

- 基本带通调制：**ASK / FSK / PSK**（各只有 2 种码元 → 1 bit/码元）
- 模拟→模拟对应 AM / FM / PM
- **QAM 混合调制**：同时调制两路正交载波的**幅度**，间接实现幅相混合。看**星座图**数出有 N 种码元 → **每码元 log₂N 比特**。
- ⚠️ 星座图用**格雷码**映射（相邻码元只差 1 bit），目的是把噪声导致的码元误判**限制成 1 个比特错**。

> 💡 **考场通用法**：不管调制方法多复杂、名字多陌生，**只关心它能调制出多少种码元 N**，然后 `log₂N`。

### 命名规则（间接给条件的常用手段）

`100BaseT` = **100 Mb/s** + **Base 基带** + **T 双绞线**

> ⚠️ 看到 **10Base-T** 要立刻反应：它等于间接告诉你①用**曼彻斯特编码** ②**争用期 51.2 μs**。2013 题 34 就是这么考的。

### 信道复用

FDM / TDM / STDM / WDM / CDM（CDMA 码片正交，用规格化内积）

## 5. 数据链路层（最厚的一章，湖科大用了 15 讲）

### 差错检测（湖科大用了 6 讲，是难点）

| 方法 | 关键 |
|---|---|
| **奇偶校验** | 只能检出奇数个错 |
| **海明校验** | `2ʳ ≥ k + r + 1`；**码距 ≥ 3 才能纠 1 位错**；2025 题 34 考过 |
| **CRC** | 生成多项式写成二进制 → 补 r 个 0 → **模 2 除**（异或）→ 余数替换那 r 个 0；接收方整除余 0 则无错 |
| **因特网检验和** | 16 位一组反码求和、**进位回卷加到末位**、最后取反；2024 题 39 考过 |

### 四种服务类型（送分题，但很多人搞不清）

> 湖科大说：熟悉那张 TCP/IP 协议全景图的话，这类题**可以秒杀**。

| 服务类型 | 典型代表 |
|---|---|
| **面向连接 + 可靠** | TCP；网络层的虚电路服务 |
| **无连接 + 不可靠** | UDP；IP（v4/v6 都是）；**802.3 以太网 MAC** |
| **面向连接 + 不可靠** | **PPP**；某些实时应用 |
| **无连接 + 可靠** | **802.11 无线局域网 MAC** |

**为什么 802.3 不可靠而 802.11 可靠？**
有线链路**误码率低**，为减小开销不要求链路层可靠，出错交给上层 TCP 处理；无线链路**易受干扰、误码率高**，所以要求链路层自己就提供可靠传输。

> 概念辨析：**"连接"**是传输前建立的逻辑关联（如 TCP 三报文握手）；**"可靠"**是保证数据的正确性、完整性、有序性。两者独立，所以有四种组合。
> ⚠️ 再次强调：以太网 CSMA/CD 虽然也重传遭遇碰撞的帧，但那只是为了让接收方最终收到没碰撞的帧，**与"确认 + 超时重传实现可靠传输"不是一回事**。

### 可靠传输三机制

**统一关系式（记这一个就够）**：设序号比特数为 `n`，发送窗口 `W_T`，接收窗口 `W_R`：

```
W_T + W_R ≤ 2ⁿ        ← 目的是让接收方能分辨新旧数据帧
```

由它可推出三个协议：

| | 发送窗口 W_T | 接收窗口 W_R | 序号比特 n | 确认方式 |
|---|---|---|---|---|
| **停止等待 SAW** | 1 | 1 | 1 | 逐个 |
| **GBN 后退 N 帧** | 代入 W_R=1 → **≤ 2ⁿ − 1** | **1** | ≥ 2 | **累积确认** |
| **SR 选择重传** | 取 W_T=W_R → **≤ 2ⁿ⁻¹** | ≤ 2ⁿ⁻¹ | ≥ 2 | 逐个 |

**湖科大总结：这三个协议只有三种考法**
1. 发送窗口与接收窗口各自的**尺寸**
2. 两个窗口相互配合**向前滑动的细节**
3. **信道利用率**的计算

### CSMA/CD（重点中的重点）

- **只能半双工**——因为必须边发边听，不可能同时收发
- **争用期 = 2τ**（往返传播时延）；10 Mb/s 以太网争用期 = **51.2 μs = 512 bit 时间**
- **最小帧长 = 争用期 × 带宽 = 64 字节**
  > ⚠️ 湖科大强调：**为保持兼容，所有以太网标准（含万兆及以上不用 CSMA/CD 的）最小帧长都是 64 字节**。收到小于 64 字节的帧一律当无效帧丢弃。
- **二进制指数退避**：从 `[0, 2^k − 1]` 取随机数 r，等 `r × 2τ`
  > ⚠️ 三个陷阱（湖科大点名）：
  > ① 争用期 **可能通过 10Base-T / 100Base-T 间接给出**，不一定直接写 51.2 μs
  > ② **k = min(重传次数, 10)**
  > ③ 重传达 16 次仍失败则丢弃并向上报告
- 检测到碰撞后除立即停发，还要**继续发至少 32 bit 人为干扰信号**
- ⚠️ **以太网提供不可靠传输**：无确认、无超时重传，收到无效帧**只丢弃、什么也不做**。**"检测到碰撞后退避重传" 与 "确认+超时重传实现可靠传输" 是两回事，别混。**

### CSMA/CA（802.11，湖科大说难度逐年上升）

- CA = 碰撞**避免**，但**并不能避免所有碰撞**，只是降低概率
- **需要确认机制实现可靠传输**（与 CSMA/CD 的不可靠形成对比）★ 高频对比考点
- 帧间间隔：**DIFS > SIFS**；RTS/CTS 预约信道，其他站按 **NAV** 推迟
- **RTS / CTS / ACK 都是控制帧，没有数据载荷**
- ⚠️ **只有一种情况不用退避算法**：检测到信道空闲，且该帧不是"上一帧成功发完后要立即连发"的帧。其余情况一律要退避。

**时序图记忆法（湖科大原话："考前反复看这幅图，实战遇到就稳稳拿下"）**

1. 记发帧顺序：**RTS → CTS → DATA → ACK**（先信道预约 → 再发数据 → 再等确认）
2. 在这四个帧之间**插入 SIFS**——想想合理不？SIFS 的作用本来就是**分隔属于同一次对话的各个帧**
3. 画出前两步，三个 **NAV（持续期）** 的值就不难记了
4. 再补两条：
   - **初始信道空闲** → 源站检测到空闲，等**一个 DIFS** 即可发送（**这就是那个唯一不退避的情况**）
   - **成功发完一帧后还有数据要发** → 必须等 **一个 DIFS + 一段随机退避时间**

> **NAV 怎么来的**：其他站读到正在传送的帧首部中的「**持续期**」字段值，就知道信道将被占用多久，据此调整自己的 NAV，这段时间内不发帧干扰。这就是 RTS/CTS 能缓解**隐蔽站**问题的原因。
> **RTS/CTS 是可选机制**，三种策略：① 无条件使用 ② 数据帧长度超过某阈值才用（帧本身很短就没必要预约）③ 完全不用。
> 局域网中信号**传播时延远小于帧的发送时延**，所以画图时一般不考虑传播时延（矩形；要考虑就变成平行四边形）。
- 术语别混：**BSSID**（AP 固化的 48 位 MAC）≠ **SSID**（无线网名字）；同一 ESS 内相邻 AP 信道至少**相隔 5 个信道**
- 考过：2017-35、2022-47、2024-36

### 随机访问协议的演进

纯 ALOHA（利用率 **18.4%**）→ 时隙 ALOHA → CSMA → CSMA/CD
> ⚠️ 纯 ALOHA 虽有确认帧，但**只判断有没有碰撞，不检错**，**不实现可靠传输**。

### 三种设备对比（必考）

| | 集线器 | 交换机 | 路由器 |
|---|---|---|---|
| 层 | 物理层 | 数据链路层 | 网络层 |
| 冲突域 | **1 个（不隔离）** | 每口一个（隔离） | 隔离 |
| 广播域 | 1 个 | **1 个（不隔离）** | **隔离** |

> ⚠️ **MAC 地址虽叫"物理地址"，但属于数据链路层，不属于物理层**——408 真题考过这个字面陷阱。
> ⚠️ 集线器可看作一根总线，**单播帧在它上面也是广播传送**。

## 6. 网络层（分值最高）

### IPv4 地址

**特殊地址（必背）**

| 地址 | 含义 |
|---|---|
| **0.0.0.0** | 本网络本主机；**可作源地址，不可作目的地址**（DHCP 客户未获址时用） |
| 主机号全 0 | 网络地址（表示网络本身） |
| 主机号全 1 | 广播地址 |
| 127.x.x.x | 回环测试（**是网络号 127，不是主机号**） |

> ⚠️ **审题陷阱（湖科大点名）**：问"该网络**包含的地址数量**" → **不减 2**；问"**可分配的**地址数量" → **要减 2**。

**别混淆的两组概念**

- **定长/变长网络号**（分类编址 vs CIDR）≠ **定长/变长子网划分**
- **找共同前缀 → 用于路由聚合**；**最长前缀匹配 → 用于查表转发**
- **默认路由条目**（路由表里的一条 0.0.0.0/0）≠ **默认网关**（一台路由器）

### 子网划分：二叉树 + 堵水法（湖科大的标准解法）

**定长 vs 变长**

| | 定长子网划分 | 变长子网划分 VLSM |
|---|---|---|
| 掩码 | 所有子网**同一个** | **可以不同** |
| 能划几个 | 只能 **2ⁿ 个** | 可以非 2ⁿ 个 |
| 各子网地址数 | 相同 | 可不同（接近按需分配） |
| 适用 | 规模相同的网络 | 规模不同的网络，地址利用率高 |

**二叉树法**：把原地址块作根。每从主机号**借 1 位**，就均分成两个子块，**前缀长度 +1，地址数减半**。
例：`/24` 有 2⁸ = 256 个地址 → 借 1 位得两个 `/25`（各 128）→ 再借得四个 `/26`（各 64，掩码 255.255.255.192）。

> ⚠️ **做变长划分时，选中的子块不能全在同一层**——全在同一层就退化成定长划分了。
> **堵水法**（2022 年群里同学提出、湖科大采纳的口诀）：选中一个子块后，**同一分支不能重复封堵**。
> 湖科大提示：408 **至今没考过"让你选划分策略"**，都是直接给定划分条件。

### 掩码心算技巧（湖科大原话）

看到前缀长度要能**立刻**写出点分十进制掩码：

- **`/26`** → 前 24 位 = 3 个 255；最后一组的高 2 位为 1 → **加权值** 128 + 64 = 192 → `255.255.255.192`
- **`/30`** → 最后一组只有最低 2 位为 0 → **减权值** 255 − 2 − 1 = 252 → `255.255.255.252`

> 规律：**前缀靠前用"加"，靠后用"减"**，哪边算得快用哪边。

### 直接交付 vs 间接交付：机器怎么判断（高频疑问）

```
N1 = 源主机 IP     & 源主机掩码
N2 = 目的主机 IP   & 源主机掩码      ← 注意仍用【源主机自己的】掩码
N1 == N2 → 直接交付；否则 → 间接交付（发给默认网关）
```

> ⚠️ **为什么不用目的主机的掩码？**——因为 **TCP/IP 根本没有提供让源主机知道目的主机掩码的机制**，也没这个必要。这是 B 站弹幕里最常见的疑问，湖科大专门解释过。
> 如果有人举出"这方法会误判"的反例，那是**子网划分本身划错了**（把 C 的地址块包含进了 A 的地址块），对应堵水法"同一分支不能重复封堵"这条规则。

### 点对点链路的地址分配（408 考过）

| 地址块 | 地址数 | 用法 |
|---|---|---|
| **`/30`** | 4 | 最小（网络地址）和最大（广播）不可分配，**剩下 2 个正好给链路两端的路由器接口** ★ 考过 |
| `/31` | 2 | 两个地址都直接分配给两端接口（需路由器特殊支持，非所有厂商有） |
| 无编号网络 | 0 | 点对点链路两端干脆不分配 IP |

> 约定俗成：**本网络默认网关的接口，一般分配"可分配的最大地址"**——但这只是默契，**不是强制规定**。

### 路由表填写（大题高频）

**直连网络路由怎么来的**：路由器接口配好 IP 和掩码后，把 `接口IP & 掩码` 一算，主机号清零，得到的就是该接口直连网络的网络地址——**路由器自己就能算出来，不用配**。

> ⚠️ 湖科大点名："**接口**"这一列指的是**路由器自身的接口**，不是对端/下一跳路由器的接口。"下一跳"列：题目只给路由器名就填名（如 R1），给了接口 IP 就填 IP。

### IPv4 分片

- 片偏移**以 8 字节为单位**
- ⚠️ **MF 位陷阱**：很多人误以为"看起来最后那个分片"就是最后一片。要看**数据载荷编号**判断，第一次分片得到的第三片才可能是原报文的最后一片。
- ⚠️ **分片可在沿途任意路由器进行，但重组只在最终目的地进行**
- 接收方有**重组计时器**，超时即使只缺一片也丢弃全部已到分片，并发 **ICMP 时间超过**报文

### ICMP（湖科大说是送分题）

**差错报告 5 类**：终点不可达、源点抑制、时间超过、参数问题、改变路由（重定向）

> ⚠️ **首部检验和发现出错 → 静默丢弃，不发 ICMP**。这是最容易被"多选式单选题"偷袭的点。

**询问类**：回送请求/回答、时间戳
**应用**：`ping` 用回送请求/回答；`traceroute` 用 **TTL 递增 + 时间超过**报文

### NAT / NAPT

- **外网主机不能主动发起到内网主机的通信**——必须先由内网发起 ★ 高频
- 基本 NAT：路由器有 N 个公网地址 → 内网**最多 N 台同时**上网
- NAPT 额外转换**端口号**，所以一个公网 IP 能带很多台
- 因特网上的路由器对目的地址是**私有地址**的数据报一律**不转发**

### 路由选择协议

> ⚠️ **IGP / EGP 是分类名，不是协议名**！RIP、OSPF、BGP 才是协议名。

| | RIP | OSPF | BGP |
|---|---|---|---|
| 范围 | AS 内 | AS 内 | **AS 间** |
| 算法 | 距离向量 | 链路状态 + Dijkstra | 路径向量 |
| 承载 | **UDP 520** | **直接 IP，协议号 89** | **TCP 179** |
| 封装看属哪层 | **应用层** | **网际层** | **应用层** |
| 更新 | 周期 30 s，只给邻居 | **可靠洪泛**，仅链路变化时 | **增量更新** |
| 度量 | 跳数，**16 = 不可达** | 链路代价 | 路径属性 |
| 毛病 | **坏消息传得慢** | 开销大 | 只求较好不求最优 |

> 湖科大提示：**按 PDU 封装看，RIP/BGP 属应用层，OSPF 属网际层；但按核心功能看，三者都属网际层。**题目问法不同答案不同。
> OSPF 分组直接封装在 IP 数据报中，目的 IP 一般为**多播地址**。
> OSPF 交换五步：**Hello → DBD → LSR → LSU（含 LSA）→ LSAck**
> ⚠️ **iBGP 防环规则**：从 iBGP 对等端收到的路由，**不能再转告给同一 AS 内的其他 iBGP 对等端**。

## 7. 传输层

### 端口

- **端口号只有本地意义**；不同主机的相同端口号无关，**TCP 与 UDP 的端口号也互不相关**
- 熟知端口 0–1023，登记端口 1024–49151，短暂端口 49152–65535
- ⚠️ **ICMP(1) / IGMP(2) / OSPF(89) 不使用传输层**，直接封装在 IP 里，括号内是 **IP 首部协议字段的值**——**这是协议号，不是端口号**

### 连接管理

- **三报文握手不能简化为两报文；四报文挥手可以简化为三报文**（FIN 与 ACK 合并时）
- ⚠️ 第三个报文段是 TCP**客户**发的**普通确认**（SYN = 0），不是"服务器的连接请求确认"——湖科大说这里最容易跳坑
- **TIME_WAIT 等 2MSL**，只有**主动关闭方**有
- 四种计时器：重传、坚持（persistence）、保活、时间等待

### 流量控制 vs 拥塞控制

`发送窗口 = min(rwnd, cwnd)`——**rwnd 是接收方给的，cwnd 是网络拥塞程度决定的**，两者别混。

### 拥塞控制（画图题）

**先记住三个题目默认的简化假定**（湖科大说 408 历年都是这么考的）：
① 数据单向传送，反向只传确认；② 接收方缓存总是够用，**所以发送窗口只由拥塞程度决定**（不考虑流量控制）；③ 以 **MSS** 为单位讨论。

**读图规则（最容易错的地方）**

- **横坐标的"传输轮次 0"不是一个轮次**，它表示初始状态，此时 `cwnd = 1`
- **每个轮次对应的 cwnd 值，是那个轮次「结束时」的值**——不是开始时

**四种算法**

- **慢开始**：`每收到一个对新数据的确认，cwnd + 1` → 结果是每个 RTT 结束后 **cwnd 翻倍**
  > ⚠️ 湖科大点名：很多人只背住"每 RTT 翻倍"这个结论，**忘了它的机制是"每确认一个就 +1"**。
  > ⚠️ "慢开始"的"慢"指的是**一开始注入网络的数据量少**，**不是指 cwnd 增长得慢**（它其实是指数增长）。
- **拥塞避免**：cwnd 到达 ssthresh 就切换，每 RTT **只 +1**（线性）
  > ⚠️ **ssthresh 不是 2 的幂时**（比如 14）：cwnd 一增长到 **14 就立刻切换**，不是等涨到 16。
- **超时** → `ssthresh = cwnd/2`，`cwnd = 1`，回**慢开始**
- **3 个重复 ACK** → **快重传 + 快恢复**：`cwnd = ssthresh = cwnd/2`，**不回 1**
- ⚠️ 湖科大提醒：**超时重传也可能发生在慢开始阶段**（不是只在拥塞避免阶段），处理方式相同
- 💡 **强信号**：题目一旦出现 **MSS（最大报文段长度）**，基本就是在暗示要考**拥塞控制**

## 8. 应用层

### 端口号（送分，必背）

| 协议 | 端口 | 承载 |
|---|---|---|
| FTP | **21 控制 / 20 数据** | TCP |
| SMTP | 25 | TCP |
| DNS | 53 | **UDP**（区域传送用 TCP） |
| DHCP | **67 服务器 / 68 客户端** | UDP |
| HTTP | 80 | TCP |
| POP3 | 110 | TCP |

> 💡 记忆法（串讲视频原创）：用 UDP 的是 **DDR** —— **D**NS、**D**HCP、**R**IP。

### DNS

- 主机→本地 DNS 用**递归**；本地 DNS→根/顶级/权限用**迭代**
- **本地域名服务器独立于域名服务器的等级结构**，其 IP 直接配置在主机上（手工或 DHCP 下发）
- ⚠️ **域名与 IP 并非一一对应**：一个域名可对应多个 IP（CDN 按地理位置返回最近的）
- **edu / gov / mil 是美国专用**顶级域名
- 域名只是逻辑概念，**不代表主机的物理位置**

### DHCP

- DORA：Discover → Offer → Request → ACK
- ⚠️ **CIADDR 字段**：初次获取 IP 的 DORA 过程中**始终为 0.0.0.0**；续租时才填当前正在用的 IP

### FTP

- **两个连接**：控制连接（21，全程保持，传 ASCII 明文命令）+ 数据连接（每传一次建一次）
- **主动模式 / 被动模式的区别只在于"数据连接由谁发起"**：主动 = 服务器主动连客户；被动 = 服务器等客户来连
- ⚠️ **FTP 没有标准化的 PDU 首部格式**（不像 DNS/DHCP 报文那样有固定字段）

### 电子邮件

- ⚠️ **邮件的信息格式由 RFC 822 定义，不是 SMTP 定义的**
- 邮件 = 信封 + 内容；内容 = 首部（From/To/Subject…）+ 主体
- **SMTP 只能传 ASCII 文本**，传不了图片/音视频/中文 → 用 **MIME** 扩展
- ⚠️ **MIME 不只用于 SMTP，HTTP 也用**
- 发信 SMTP「推」，收信 POP3/IMAP「拉」

### HTTP（每年必考的时间计算）

设请求 1 个 HTML + n 个对象：

| 方式 | 总时间 |
|---|---|
| **HTTP 1.0 非持久** | `2(n+1)` RTT |
| **1.0 非持久 + 浏览器并行连接** | 视并行数而定 |
| **1.1 持久 + 非流水线** | `1 + (n+1)` RTT |
| **1.1 持久 + 流水线** | **2 RTT** |

> ⚠️ 湖科大提醒：以上都**没考虑 TCP 拥塞控制**。**若题目给了 MSS，就要把慢开始也算进去**——这是这类题加难度的方向。
> Cookie 识别码由 **Web 服务器**产生并通过 HTTP 响应发给浏览器。

## 9. 其他考点（P53–P54）

- **VLAN**：access 口接主机、trunk 口接交换机；PVID 相同则去标签转发
- **SDN**：**南向接口（OpenFlow）→ 数据平面下发流表**；北向接口 → 上层应用；东西向 → 控制器之间（2022 题 37 考过）
- **IPv6**：
  - 地址 **128 位**，首部**固定 40 字节**；**扩展首部算作数据载荷**（对比 IPv4：20 + 最多 40 = 最长 60 字节）
  - ⚠️ **连续 0 压缩（`::`）在一个地址中只能用一次**，否则有歧义
  - 不保证可靠交付，需 **ICMPv6**；ICMPv6 **合并了 ARP** 的功能
  - 过渡：**双协议栈 + 隧道技术**
- **PPP**：协议字段 `0x0021` 数据 / `0xC021` LCP / `0x8021` NCP；同步用**零比特填充（5 个 1 后插 0）**，异步用字节填充
- **IP 组播**：组播 IP 低 23 位 → 组播 MAC，前缀固定 **01-00-5E**；IGMP 三种报文（成员报告 / 成员查询 224.0.0.1 / 离开组 224.0.0.2）
- **移动 IP**：永久地址、归属代理、外地代理、转交地址；**三角路由**问题及其优化

## 11. 高频易错点总清单（背这一页）

**概念混淆类**
1. **传输时延 ≠ 传播时延**（一字之差，弹幕重灾区）
2. **频率带宽（Hz）≠ 速率带宽（bit/s）**
3. MAC 地址叫"物理地址"，但属于**数据链路层**
4. **IGP/EGP 是分类名**，RIP/OSPF/BGP 才是协议名
5. **默认路由条目 ≠ 默认网关**
6. **路由聚合找共同前缀 ≠ 查表用最长前缀匹配**
7. **定长/变长网络号 ≠ 定长/变长子网划分**
8. **协议号（TCP 6 / UDP 17 / ICMP 1 / IGMP 2 / OSPF 89）≠ 端口号**
9. **"包含的地址数" 不减 2，"可分配的地址数" 减 2**
10. 上层 PDU = 本层 SDU；**SDU + PCI = 本层 PDU**（别说反）

**机制类**
11. 跨网段通信，ARP 请求的是**网关 MAC**
12. **IP 全程不变、MAC 逐跳变**
13. 交换机隔离冲突域**不隔离广播域**；路由器两个都隔离
14. `发送窗口 = min(rwnd, cwnd)`
15. 超时 → cwnd = 1 回慢开始；3 个重复 ACK → **快恢复，不回 1**
16. GBN 发送窗口 `≤ 2ⁿ − 1`，SR 是 `≤ 2ⁿ⁻¹`
17. 片偏移单位是 **8 字节**；**分片随处可做，重组只在终点**
18. **以太网不可靠**（无确认无重传）；**CSMA/CA 有确认**
19. **外网主机不能主动发起 NAT 内网通信**
20. 三次握手不能简化，**四次挥手可以简化为三次**
21. TIME_WAIT（2MSL）只有**主动关闭方**有
22. **IPv6 的 `::` 只能用一次**

**计算类**
23. 最小帧长 = **争用期(2τ)** × 带宽；所有以太网都是 **64 字节**
24. 退避 `k = min(重传次数, 10)`
25. 香农公式给 dB 必须先反解
26. 曼彻斯特编码**波特率 = 2 × 比特率**
27. 看到 **10Base-T** = 曼彻斯特编码 + 争用期 51.2 μs
28. 看到 **MSS** = 暗示考拥塞控制
29. 题目只给带宽 → 数据传输率就按带宽算（木桶效应）
30. 首部检验和出错 → **静默丢弃，不发 ICMP**
